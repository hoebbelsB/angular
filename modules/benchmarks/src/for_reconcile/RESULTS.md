## Memory

Browser: `node driver/run.mjs <n> <rounds> <reps> mem`. Chrome runs with `--enable-precise-memory-info` and
`--js-flags=--expose-gc --min-semi-space-size=512 --max-semi-space-size=512`, so no GC runs inside a tick
(checked: a 162 MB garbage-only loop shows up 1:1 in `usedJSHeapSize`).

- `alloc` = V8 heap allocated by one update (signal set + `appRef.tick()`), garbage included.
- `retained` = heap after GC with `next` rendered minus heap after GC with `base` rendered (GC runs twice:
  after a single `gc()`, up to ~50 KB of the previous update's garbage can survive until the next one).
- No leak in either build: the post-GC heap with `base` rendered stays flat over 12–25 consecutive updates.
- Blink/Oilpan memory (DOM nodes) is not part of `usedJSHeapSize`; DOM work per update is in the DOM column above.
